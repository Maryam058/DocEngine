## Project Overview

DocEngine is a documentation platform built on MkDocs + Material for MkDocs, with a Python "docs-as-code" pipeline layered on top that ingests source material (PDFs, Markdown, OpenAPI specs, Jira exports), runs it through an editorial review workflow, and publishes it into the `docs/` site.

## Commands

Setup:
```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Local preview server:
```bash
python -m mkdocs serve
```

Build static site (output to `site/`):
```bash
python -m mkdocs build
```

Pipeline tools (unified CLI via `run_pipeline.py`):
```bash
python run_pipeline.py import-pdf <pdf_file> [--section user-guide|api|release-notes]
python run_pipeline.py release-notes <jira_csv>
python run_pipeline.py api-docs <openapi_spec>
python run_pipeline.py validate
python run_pipeline.py ingest <source> [--source-type auto|pdf|markdown|ai-markdown|text|openapi] [--section ...] [--actor ...]
python run_pipeline.py review <document_id> --action submit|approve|reject [--actor ...]
python run_pipeline.py publish <document_id> [--actor ...]
python run_pipeline.py status [document_id]
```

There is no test suite or linter configured in this repo. CI (`.github/workflows/deploy.yml`) only installs `requirements.txt` and runs `python -m mkdocs build` on push to `main`.

## Architecture

- `mkdocs.yml` — site config: nav structure, Material theme, plugins, extra CSS/JS. Adding a page requires both creating the Markdown file under `docs/` *and* adding it to the `nav:` tree here.
- `docs/` — the MkDocs source tree (`docs_dir`). `docs/.workflow/` holds editorial workflow state; `docs/ai-logs/` holds audit/deploy-error logs generated by the pipeline (not hand-authored).
- `tools/` — the pipeline package, all built on shared path constants from `tools/__init__.py` (`DOCS_DIR`, `USER_GUIDE_DIR`, `API_DIR`, `RELEASE_NOTES_DIR`, `ASSETS_DIR`):
  - `import_pdf.py` — converts a PDF to Markdown, extracts images, auto-detects or accepts a target section.
  - `generate_api_docs.py` — generates API doc pages from an OpenAPI spec.
  - `generate_release_notes.py` — generates release notes from a Jira CSV export.
  - `validate_docs.py` — checks Markdown links, images, headings, tables, and MkDocs nav references for consistency.
  - `editorial_workflow.py` — the orchestration layer: tracks each document through a state machine (`New → Draft → Human Review → Approved/Rejected → Validation → Commit → MkDocs Build → Deploy → Published`), persists state as JSON (`docs/.workflow/workflow-state.json`), and writes an audit trail to `docs/ai-logs/editorial-audit-log.md`. `publish_document()` chains validation, build, and deploy stages together.
  - `editor-server.py` / `extract_images.py` — supporting utilities.
- `run_pipeline.py` — single argparse entry point wrapping all of the above into subcommands (`import-pdf`, `release-notes`, `api-docs`, `validate`, `ingest`, `review`, `publish`, `status`). This is the intended way to invoke pipeline functionality rather than calling `tools/*` modules directly.
- `api/` — `openapi.yaml` (spec source) and `publish.py` (API-related publishing logic, separate from the editorial workflow above).
- `overrides/` — MkDocs Material `custom_dir` theme overrides.
- `markitdown/` — a vendored third-party project (own README/license/Dockerfile/CI) used as a dependency/tool for document conversion — not part of DocEngine's own source; don't treat its structure or conventions as this repo's own.

## Key conventions

- Document sections are one of exactly three values throughout the pipeline: `user-guide`, `api`, `release-notes`. `import_pdf.py` auto-detects the section when not given explicitly.
- Editorial workflow source types: `auto`, `pdf`, `markdown`, `ai-markdown`, `text`, `openapi`.
- Every document moving through `editorial_workflow.py` gets an audit actor (defaults: `"AI"` for automated ingestion, `"Human"` for review actions) recorded in the audit log.
